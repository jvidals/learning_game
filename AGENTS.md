## Accepted product decisions

- Appearance: AMOLED **Midnight Rainbow** dark mode uses true-black page backgrounds, vivid rainbow accents and dark drawing/game surfaces. Parent Settings offers System (default), Light and Dark per player; Changes apply immediately and save automatically; Back keeps accepted changes. Follow [the dark-mode design reference](docs/dark_mode.md) when extending any UI. Keep original unicorn/equipment colors.

- Identity: **Learning Corner** centers on learning games and companions. Call the main screen **Home** and return actions **Back to home**; use neutral app-wide wording (Counting, Player progress). Unicorns and rainbows are the current companion theme, not a permanent requirement for every future theme. Preserve the clean Home and large, accessible controls.
- Home greeting: show **Hi, [saved active profile name]!**, or **Hi!** when no profile is available. It follows committed profile switches/renames, stays silent, and wraps long names at large text. The app/Android name remains Learning Corner.
- Future direction: add another companion/theme to broaden appeal, including for boys; choices should be open to any player. Specific companion artwork and selection remain separate future work. Keep cosmetic themes independent of learning rules and progress ownership. Current My unicorn, artwork, launcher icon and Light/Midnight Rainbow palettes remain approved.
- Branding changes must preserve the Android application ID, signing key, Dart package/API names, platform channel and saved identifiers. The current distributable is `artifacts/learning-corner.apk`; old garden identifiers remain intentional compatibility details.
- Flutter; Android first; modern phones and tablets, primarily a Google Pixel 9 Pro.
- Voice is reserved for learning prompts: Uppercase letters, Lowercase letters, Number hunt and Sight Words use spoken targets; Letter friends has optional spoken instructions. Home and identification toggles share the saved sound choice, defaulting on only when unset. Muted identification gently pulses the speaker (static with reduced motion) without revealing the answer; Show a hint is always explicit, including audio failure. Unmuting an unanswered identification plays its target. Letter friends initializes its visit-local optional toggle from saved sound; enabling it is silent. Rewards, retries, ordering games, Tap Challenge and My unicorn are silent. Preserve visual help and screen-reader semantics.
- Completely offline from first launch, including speech. No network permissions, runtime downloads, accounts, ads, analytics, or backend.
- Home → category → game, with direct round continuation and optional rewards. Home offers Letters, Numbers, Words and Writing, Reflex and My unicorn. All learning categories open an activity list.
- Direct APK installation for testing. Sharing may come later; hosting and public distribution are not current requirements.
- Ease of maintenance matters: plain Dart game rules, Flutter widgets, and a small Android audio/storage boundary. Avoid unnecessary packages or architecture layers.

These choices are already approved. Do not re-ask framework, device, navigation, or offline questions just because a skill asks for initial clarification.

## Behavior to preserve

- Profiles are local shared-device players: the upper-left unicorn portrait opens a minimal picker, the last player resumes, and all progress/settings belong to stable player IDs. Add/edit reuse the Settings gate; delete confirms and must leave one player. Existing saves migrate to Player 1. New players use app defaults. Reset affects only the active player and preserves their name/settings. Keep pending writes attached to their originating player and block switches until they save or retry. Portraits use cached static production head art with saved mane/headwear.


- Writing uses one saved shuffled alphabet per player; either case may be completed first. The case badges switch freely and retain each case's temporary ink during a visit. Both forms earn 10 XP together, once per pair/cycle. Clear preserves completion, Skip advances without XP, and the Aa–Zz picker is practice-only with a Shuffled alphabet option to resume the saved sequence. Check/Continue stay visible in the fixed bottom action area. Manual Next is always required. Absent Writing data initializes on entry; malformed existing data must not be discarded. Ink is temporary; saved partial completion resumes across visits.

- Tablet layout: Home's profile/sound/Settings header spans the safe screen width independently of centered activity content. Writing windows with shortest side ≥600 logical pixels place spare space above the pads, with Skip in the information header; constrained layouts scroll and Check/Continue stay fixed. Preserve phone/narrow-window flow and existing pad sizes. This is a reach improvement for a basic touch stylus, not hardware palm rejection; Clear remains the erasing control.

- Each five-question round balances correct-answer slots with counts **2, 2, 1**, randomly choosing the singleton slot and shuffling order. Cover every activity and Next round. Unrestricted independent shuffling previously produced repetitive positions.
- Tap Next and Haptics default on. Standard learning games and ordering boards show saved 50 XP inline and offer Next round, with optional Rewards. Tap Next off advances questions 1–4 after 800 ms and starts another round after two visible seconds of saved completion feedback; accessible navigation always requires a tap. Never continue before saving succeeds. The gift button opens a sheet at any time, pauses input/timers/speech, and returns to the same work; closing restarts the applicable full delay. Gifts remain banked. Preserve interruption cancellation and once-only feedback. Writing, 2048 and Tap Challenge retain their own pacing.
- Correct answers stop speech and show a short rainbow sparkle/pop animation. Do not restore the repetitive “You found it! A little bit of rainbow magic!” voice-over. Static success text is intentional.
- Target letter/number prompts have a **400 ms pause** immediately before the target; bundled audio uses `target-pause-v2` processing. Preserve the offline recordings and manifest checks.
- Each player has four independent inclusive ranges, default **0–10**, with at least three values: Number hunt/Number Order are capped at **100**, How many?/Make a group at **20**. A parent-gated upper-right game button edits the range; the compact settings icon above the range replaces the play arrow on the right of its Numbers card and opens that game/editor as a separate accessible action. All five Numbers cards share one height (102 dp at normal phone text), expanding together for large text; there is no extra footer. Edits autosave; closing restarts once only if the final range differs, after pending saves succeed. Unchanged ranges preserve work; unfinished rounds earn no XP. 2048 is independent.
- Sight Words uses three independent bundled packs (8/13/22 words), default Pack 1. Targets and distractors come only from enabled packs. Parent settings keeps pack choices in a collapsed expansion; removing the final enabled pack is prevented with an immediate accessible explanation. Preserve uppercase I, natural word pronunciation, the 400 ms target pause, saved pack selection through sound/case changes and reset, and whole-word readability at large text. Word identification games always use full-width, vertically stacked answer cards, including Pack 1 alone, landscape and tablets; do not switch layout based on word length or enabled packs.
- Settings use a parent gate and apply/autosave every valid change; Back keeps changes. Appearance previews immediately. Prevent fewer than three distinct Letter Sounds and an empty Sight Word selection. The shared controller serializes settings writes, coalesces later edits, retains an exact failed snapshot before newer queued edits, and pins them to the originating player. Settings editing and Back remain available during settings saves; gameplay mutations, profile switching and reset wait until writes finish. Confirmed reset preserves all settings.
- A completed round earns 50 XP at the fifth correct answer. Levels earn companion choices. Persist before reporting success. Storage writes deliberately have no timeout; one shared controller prevents overlapping operations and retains failed writes for retry after navigation.
- Game Back returns to its category; reward-sheet **Back to home** returns to the root home route. Next round preserves activity and all learning settings. Tap Challenge Back returns to Reflex; its Back to home returns to root Home.
- Respect reduced motion, large text, audio interruption, backgrounding, and disposal. Tap Challenge backgrounding pauses its clock and targets until explicit Resume; abandoned unfinished rounds earn nothing.
- Upgrade to 0.4.0 intentionally clears old flowers, preserving number settings. Never reinitialize an existing player progress document or silently discard malformed data; recovery reset stays parent-gated.

- Reflex → **Tap Challenge** replaces Adventure completely. Free 30-active-second rounds use generic regular/bonus/hazard roles: unicorn skin star +1, rainbow +3, cartoon bomb −2, score floor zero. Nine slots, up to three targets, 600 ms spawning, 1.8 s expiry; shuffled batches of six regular/two bonus/two hazards. Each target scores once. No relaxed mode or play entitlements. The first positive completed score and each later strictly higher final score earn 50 XP, atomically with the per-player best and gifts. Ties/lower scores earn none. Skins change illustrations/labels, not rules or score ownership; future companion selection remains separate work.
- Shared `PlayerProgress`/`ProgressController` retain the save guard. Version 3 retires board fields and relaxed settings while preserving all other player data; legacy readers remain necessary migration code. Malformed profiles must remain recoverable. No Adventure screen, runtime movement hooks, scenery or retired narration remains bundled.

- Letter Sounds uses isolated target sounds only, with parent-selected basic lowercase letters (short vowels/common consonants; q/x deferred). c/k share /k/ and each question must have three distinct sound choices. Hints use bundled reference pictures and remain explicit. Use phonics-directed synthesis rather than the defective single-letter SSML path; preserve separate sound processing and all existing target recordings.
- Counting activities How many? and Make a group stay silent and companion-neutral. Their activity icons use generic circles, triangles and squares: a question mark with three shapes for How many?, five clustered shapes for Make a group. Keep these suitable for future companion themes. Objects and empty slots must have no individual boxes, including marked items and hints; retain spacing and check badges. Their independent per-player ranges allow any inclusive bounds within 0–20, default 0–10; each needs at least three values. Make a group always starts empty and caps additions at its own maximum. Marks never automatically display totals; build a group requires Check, including zero. Keep fixed Check/Next controls, stable objects, explicit visual hints and the shared durable five-question/50 XP reward flow. New activity narration should be added only where the learning task requires audio; use pictures wherever possible.

## Development safeguards

- Use `tools/build_apk.sh` and `tools/install_apk.sh`; local executable overrides are in the runbook. Use `adb install -r` to preserve progress. Verify the device serial before interacting with a phone or emulator.
- Test APKs use this computer's debug signing key even in release mode. Preserve it for updates. Do not uninstall to work around a signature mismatch without the user's direction.
- Normal builds reuse bundled audio and require no cloud synthesis. For intentional generation, use explicit personal configuration/account/project flags from the runbook. **Do not change the active work gcloud configuration, account, project, or ADC.** Never store credentials or tokens in the project.
- Do not wipe or repurpose the user's `Medium_Phone_API_36.1` emulator. Prior tests used a separate disposable AVD under `/tmp`.
- Standard `flutter analyze` previously hit the host's exhausted file-watcher limit. Report that limitation accurately; the watcher-free fallback does not replace full Flutter linting. Do not change system limits or stop unrelated processes as a routine workaround.
- Git was initialized on 2026-10-17 (`main`, no remote). Earlier handoff notes saying no repository existed are historical. Commit only when the user asks; `.gitignore` deliberately excludes `artifacts/`, APKs, `docs/screenshots/`, retired art and agent skill links.
- Commits pass through the gitleaks pre-commit hook (`git config core.hooksPath tools/git-hooks`; see the runbook). Never bypass it with `--no-verify` or allowlist a finding without the user's explicit approval; remove the secret instead.
- Root-level `PXL_*` (Pixel camera) and `Screenshot_*` (Android screenshot) images are the user's feedback on the app. Read them when the user refers to them; don't move, edit, delete or commit them (they are ignored).

Run checks appropriate to code changes and record their actual outcomes. For a new APK, update the version as appropriate, checksum, and current validation notes. Distinguish historical results from checks run in the current session. Documentation-only work does not need an APK rebuild.
